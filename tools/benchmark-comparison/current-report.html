Methodology & limitations

  • Match by exact scenario name and metric name in the structured benchmarkResult embedded in the original HTML reports. CSV exports are not used because their titles contain unescaped commas and empty fields are collapsed.
  • Change = (current / previous − 1) × 100. Time saved = previous − current. Percent changes use unrounded values. A zero previous duration has no defined percentage.
  • Summary cards cover all comparable scenarios for the selected pair and metric, independent of search. The geometric mean of current / previous ratios weights scenarios equally; it is not a total workflow time. Only positive durations enter that mean.
  • Ranges describe observed variation, not confidence intervals. The single current measurement cannot estimate current variability; no significance tests or causal claims are made. Run numbers are not paired observations.
  • Cache order is Gradle User Home / Gradle Daemon / IntelliJ caches. Project caches are cleared with cold IntelliJ caches per performance.scenarios. Build-script changes start warm / warm / warm.
  • Dependency addition (Gson) has no measurements. The gradle-xxh3-hash and lookahead-deps reports only contain the fully cold scenario. “Not recorded” and “No measured samples” are distinct from zero.
  • Total, Gradle, and IDE durations come directly from the profiler. Independently calculated component medians need not sum to the total median. Repeat runs under controlled conditions before interpreting small differences.
